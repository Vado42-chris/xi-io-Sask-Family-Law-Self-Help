# Claude adapter — xi-io managed work

This is a thin Claude discovery adapter. It does not define an independent Claude-specific workflow, planning system, permission policy, or mutation authority.

Before consequential work in this repository, read in order:

1. `docs/ops/SFL-PUBLIC-MANAGED-WORKER-CONTRACT-v1.md`
2. `docs/ops/ACTIVE_WORK_CHECKPOINT.md`
3. `docs/ops/CURRENT_LANE_STATUS.md`
4. `docs/ops/SFL-GITHUB-EXECUTION-PLAN-2026-08-12.md`
5. run `npm run current:situation` when Git/GitHub access is available to join the tracked custody rules with live exact-head GitHub attestations;
6. `AGENTS.md`
7. `README.md`
8. `docs/INDEX.md`
9. only then task-specific source/code/evidence required by the admitted work.

For project-startup, process-freshness, or re-onboarding questions also read:

`docs/ops/SFL-REONBOARDING-DELTA-2026-08-12.md`

The xi-io framework repository is private. You are **not expected or required to access it**. The public managed-worker contract is the disclosure-safe local projection of the framework obligations required for work in this repository.

Tracked checkpoint/lane files declare durable custody, required evidence classes and fail-closed rules. They are **not** same-commit hosted-CI attestations. `npm run current:situation` joins the exact local HEAD to live GitHub PR/Actions evidence. If live evidence is unavailable, stale, contradictory, or does not match the exact HEAD, report `UNKNOWN/BLOCKED`; do not upgrade a tracked status sentence into a live proof.

If the local contract, checkpoint, current lane, execution plan, or live resolver does not resolve a required rule, authority, source state, mutation lane or validation requirement, report `UNKNOWN/BLOCKED` and do not invent the missing framework rule.

Do not infer current work from newest branch, PR, commit, issue comment or chat history. The three planning/work planes are intentionally separate:

```text
strategic/waterfall intent
!= agile/ready-work plan
!= active execution/mutation custody
```

Do not create a branch, write files, merge, release, deploy, transmit, or broaden scope merely because the user requested work. First resolve the current repo evidence, preflight dimensions and mutation-admission state required by the public contract.

Provider/model capability does not broaden authority.

Public conformance examples in this repository are regression fixtures, not an unseen answer key for final qualification. A final external-worker qualification should use evaluator-held holdout scenarios not visible in the worker's repository or Git history.
